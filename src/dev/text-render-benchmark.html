Measurement method and limits
  • Deterministic ASCII prose, tab-indented code, a 6,000-character unwrapped row, and a board containing 24 large textboxes. Every mode receives the same objects, viewport rows, transforms, color, and prepared glyph positions. There is no horizontal text culling, pan/zoom delay, or adaptive omission in this harness.
  • Layout + plans is a separate cold measurement. Cold retained is the first draw after clearing the raster cache, with layout already prepared. A font measurement cache reset precedes each case.
  • Warm paths receive four warmup iterations. Samples rotate the order of direct, retained, image, and empty paths to reduce ordering bias. Every path in a run uses the same completion method. Each sample clears the destination, applies the transform, draws, and performs the selected completion operation before stopping the timer. JSON reports submission time and an empty-destination completion baseline separately.
  • Bitmap snapshot uses a hidden OffscreenCanvas destination and calls transferToImageBitmap().close() after drawing. This finalizes a snapshot without reading destination pixels into CPU memory. Times include snapshot transfer and resource handling. They are snapshot completion timings, not GPU fence timings, presented frames, or end-to-end application FPS. The source bitmap is prebuilt outside timing; the destination is cleared before the next sample.
  • CPU readback uses an HTML canvas destination and requests the entire canvas with getImageData. This forces CPU-readable pixel completion but includes readback overhead and may change browser canvas acceleration heuristics. This mode remains useful as a readback stress comparison. Bitmap snapshot is disabled when the required OffscreenCanvas APIs are unavailable; the page then selects CPU readback and explains the fallback.
  • Direct explicitly replays the existing plan's fillText calls. Retained calls the real drawTextLineRange. The image reference is a prebuilt, same-resolution bitmap of exactly the direct output, drawn once under the same transform; its creation is excluded. It is a lower-bound compositing reference, not an image decoding benchmark.
  • Draw calls are counted in separate, untimed passes on the destination context. Raster-construction work is represented in cold time and cache diagnostics. Cache bytes are reported by the implementation; destination/image pixel storage is separately estimated at four bytes per pixel. Browser/GPU overhead and JavaScript heap are not included in that estimate.
  • Run in a foreground tab, close unrelated heavy work, and compare within the same browser/device. Differences at fractional positions can reflect bitmap resampling. Inspect visual samples in addition to timings. No text-editing or clipboard behavior is changed by this page.

Mounted canvas animation comparison

24 large textboxes · 25% zoom · selected DPR · 90 measured frames per path

This comparison draws into the visible canvas below with its default 2D context, without pixel readback or bitmap transfer. Four blocks run direct, retained, retained, direct; each has 10 warmup frames and 45 measured frames. Both paths draw the same prepared rows and all their tiles, with an identical repeating 0.375px translation step. Keep this canvas visible and the tab in the foreground.

Draw submission measures callback work. The interval until the next animation callback measures actual mounted-canvas rAF pacing, including scheduling and rendering pressure. These intervals are not precise GPU latency, confirmed presentation timestamps, or a full application interaction benchmark.
