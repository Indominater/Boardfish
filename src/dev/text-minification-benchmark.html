Method and limits
  • Run all measures 10% and 12.5% at DPR 1 and 2. DPR changes backing-store resolution while both panels retain their CSS dimensions. The 12.5% case aligns ordinary text baselines to integer physical pixel rows.
  • Phase sweeps move eight isolated repeated-character lines horizontally and vertically through 64 positions spanning one physical pixel. Each line remains fully inside the canvas. Integrated row brightness measures retained ink, independently of where that ink lands. This detects disappearing punctuation and row brightness pulses; it does not require identical pixels while moving.
  • Pixel readback and PNG capture occur only in untimed phase sweeps or after measured blocks. Per-row energy samples, minimum, maximum, mean, and peak-to-peak percentage are included in JSON.
  • Dense panning uses live getTextLayoutForViewport calls on three separate 100,000-character textboxes. Four 60-frame blocks alternate previous/current then current/previous, with 12 warmup frames per block. Each renderer owns independent layout objects. Camera paths cross row and 64-row chunk boundaries.
  • CPU submission includes visible-object filtering, live viewport layout, and GPU command submission. RequestAnimationFrame intervals include browser scheduling; they are not direct GPU timings or confirmation of presentation. No readback, GPU finish, fence, or screenshot occurs inside timed frames.
  • Keep both panels fully visible in a foreground tab. Resource counter deltas distinguish geometry preparation from recurring camera updates. To compare the old renderer, run git show 07aa2fa:src/js/gpu_renderer.js > src/dev/gpu-text-before.js and open this page with ?baseline=1; remove the temporary file afterward. Without a baseline, both panels use the current renderer and JSON identifies the comparison as unavailable.
