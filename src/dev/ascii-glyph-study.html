Boardfish ASCII glyph study

Isolated diagnostic using the actual Boardfish font, layout, draw plans, and current line raster cache. The GPU prototype retains glyph instances and draws one instanced batch. All three paths submit the same fixed rows, without horizontal culling or delayed painting.

Canvases stay at 400 × 256 CSS pixels; no CSS rescaling is applied. DPR is an explicit test setting, and the JSON records the actual browser DPR. Compare at matching DPR for a physical-pixel sharpness judgment. PNG links export backing-store pixels from static previews, outside timed frames.

Method and limitations
  • Three rotated rounds use direct → retained → GPU, GPU → direct → retained, and retained → GPU → direct. Each block has six warmup frames and 30 measured frames. The same repeating fractional pan sequence is used in every block. Only the active path changes during a block; the other mounted canvases remain static.
  • CPU draw submission time excludes preparation. The interval to the next requestAnimationFrame includes browser scheduling and rendering pressure, and is not a GPU timer or confirmed presentation timestamp. No pixel readback, bitmap transfer, GPU finish, or fence occurs in timed frames.
  • Cold atlas generation, upload submission, upload-plus-finish, instance preparation, and current raster preparation are reported separately. The cold GPU finish is outside frame measurements; it drains prior commands on that context. Memory reports resource dimensions, not complete browser or driver allocation.
  • The atlas uses Canvas2D white glyph alpha at exact requested density, with 4 × 4 quarter-pixel phase variants. Glyph baselines are rounded independently to the nearest quarter of a device pixel in the shader. This changes positions by up to 0.125 device pixel per axis. It is grayscale coverage, not ClearType; no gamma correction or font hinting beyond the browser's source rasterizer is added.
  • This is a reading-size prototype, with immediate atlas rebuilds on density changes. It does not solve arbitrary continuous zoom, large zoom, image/text stacking, context-loss recovery, editing, or a full GPU board compositor. It does not establish a production speedup or a universal sharpness improvement.
  • Objects are selected once by intersection with the viewport plus a 16 CSS-pixel margin for the fixed pan path. Selected objects use the existing vertical layout range, with every character of each selected row retained horizontally. Objects and rows stay identical across every path and frame. GPU instances use individual characters. Existing direct plans sometimes group verified pairs, which may still differ from individual glyph rasterization under some browser/scale conditions.
  • Run in the foreground with all three panels visible. JSON records visibility and viewport intersection; offscreen or background runs are not equivalent. There is no automated pixel-error or sharpness score.
