Method and limits
  • Reading and dense comparisons rotate four blocks, alternating which path runs first. Each path receives 90 measured frames and 12 warmup frames. Only the measured panel redraws; the other panel stays mounted and static. Content and selected rows remain identical across paths and frames.
  • Continuous zoom visits 180 unique scales from 0.18 to 4.0 on each path, with fractional pan. It immediately redraws every frame at that scale. Its first-visit frames are measured without scale warmup. Layout selection is fixed at the largest world viewport so neither path adds horizontal culling or motion-dependent quality.
  • CPU submission and requestAnimationFrame intervals are distinct metrics. No GPU finish, fence, readback, screenshot, or timer query occurs inside timed frames. Frame intervals include browser scheduling; they are not GPU execution or confirmed presentation times.
  • Cold first-draw preparation, GPU resource statistics before/after runs, and numeric counter deltas are reported separately. Atlas download/decode/upload timing is retained from renderer initialization. Native PNGs and pixel probes run only outside timing.
  • Lifecycle checks exercise content replacement, wrapping width, movement, removal, reused IDs, and repeated static frames. Context restoration is an explicit separate action. Pixel checks verify nonblank text and known opaque image order; human inspection of the PNGs is still required for small-text quality.
  • Scale and precision checks visit 10% through 1000% immediately, with a glyph stem centered at high zoom. Moving both object coordinates to ten million world units and compensating the camera must preserve the same final pixels without geometry uploads. Native reading samples at 16, 20, and 28 device pixels per em are exported separately.
  • Run with both panels fully visible in a foreground tab. DPR is an explicit backing-store setting; JSON also records the browser DPR. Use the native PNGs to inspect pixels without browser scaling.
